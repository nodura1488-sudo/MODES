# Lavunio Authors and Teams

> Статус: план на будущее. Сейчас у режимов есть поле автора/соавторов, но нет полноценных авторских аккаунтов, команд и публичных страниц команд. Этот документ описывает, как это сделать.

## 1. Цель

- Дать игроку понятный путь: **стать автором → создать команду → опубликовать режим**.
- Сделать раздел **«Команда»** для авторов: свои режимы, участники, профиль, статистика.
- Сделать публичные страницы команд для игроков: описание, участники, режимы, новости.
- Разделить роли: игрок, автор, участник команды, владелец команды, модератор Lavunio.
- Не ломать текущие режимы и автора `TM`.

## 2. Роли

### Платформенные роли

- `player` — обычный игрок.
- `author` — может создавать режимы и команды.
- `moderator` — проверяет режимы, жалобы и заявки.
- `admin` — полный доступ.

### Роли внутри команды

- `owner` — владелец команды.
- `admin` — управляет командой и участниками.
- `publisher` — создаёт режимы, релизы и загружает файлы.
- `designer` — оформляет страницы, обложки и скриншоты.
- `member` — состоит в команде, но не публикует.

## 3. Как стать автором

### Вариант для MVP: заявка + ручная проверка

1. Игрок создаёт аккаунт Lavunio и подтверждает email.
2. В лаунчере нажимает **«Стать автором»**.
3. Заполняет заявку:
   - отображаемое имя;
   - название команды или «публикую один»;
   - описание;
   - ссылки;
   - какие режимы планирует выпускать;
   - опыт;
   - согласие с правилами магазина.
4. Заявка получает статус `pending`.
5. Модератор проверяет и ставит `approved` или `rejected`.
6. После `approved` пользователь получает роль `author`.
7. Автор создаёт команду или публикует как индивидуальный автор.

### Позже: открытая регистрация авторов

- Автор получает роль автоматически после подтверждения email и капчи.
- Первый релиз всё равно проходит ручную модерацию.
- Ограничения: лимит черновиков, лимит размера, антиспам.

### Статусы заявки

```text
none → pending → approved
                 ↘ rejected
approved → suspended
```

### Требования

- Подтверждённый email.
- Согласие с правилами.
- Уникальное имя команды и slug.
- Запрет на выдачу себя за другую команду.
- Для владельцев команд позже — 2FA.

## 4. Модель команды

Команда — это публичный издатель режимов.

```text
Пользователь
   ↓
Заявка автора
   ↓
Команда (team)
   ├─ профиль
   ├─ участники и роли
   ├─ режимы
   ├─ релизы
   ├─ статистика
   └─ подписчики (позже)
```

### Правила

- Один пользователь может быть в нескольких командах.
- Режим принадлежит одной команде или одному автору.
- Соавторы указываются отдельно через `mode_authors`.
- Контент команды принадлежит команде, а не участнику.
- При уходе участника его авторство в уже опубликованных режимах сохраняется.
- Команду нельзя удалить жёстко: только архивировать.
- Slug команды можно менять, старый slug должен редиректить.

## 6. Профиль команды

Публичные поля:

- название;
- slug;
- аватар;
- баннер;
- описание;
- ссылки;
- статус проверки `verified`;
- дата создания;
- участники;
- режимы;
- новости;
- статистика;
- подписчики.

Настройки:

- `join_mode`: `invite` / `request` / `open`;
- кто может создавать режимы;
- кто может приглашать;
- отображение участников;
- архив.

## 7. Раздел «Команда» в лаунчере

Пункт sidebar виден, если пользователь — автор или участник команды.

### Вкладки

1. **Обзор**
   - мои режимы;
   - черновики;
   - на модерации;
   - опубликовано;
   - скачивания и установки;
   - последние события.

2. **Мои режимы**
   - список режимов команды;
   - статусы;
   - редактирование;
   - обновление;
   - статистика;
   - переход на публичную страницу.

3. **Команда**
   - профиль команды;
   - аватар и баннер;
   - описание и ссылки;
   - preview публичной страницы;
   - настройки вступления.

4. **Участники**
   - список участников;
   - роли;
   - приглашения по коду/ссылке;
   - заявки на вступление;
   - исключение и смена ролей.

5. **Статистика**
   - скачивания;
   - установки;
   - активные игроки;
   - обновления;
   - удержание (позже).

6. **Настройки**
   - slug;
   - верификация;
   - архив команды;
   - передача владения.

### Пустое состояние

Если пользователь ещё не автор:

```text
Хочешь публиковать режимы?
[Стать автором]
```

Если автор без команды:

```text
Создай команду или публикуй как индивидуальный автор.
[Создать команду]
```

## 8. Публичная страница команды

Доступна игрокам из:

- карточки режима;
- имени автора;
- поиска;
- ссылки.

Содержимое:

- шапка: аватар, название, verified, описание, ссылки;
- кнопка «Подписаться»;
- кнопка «Вступить» (если `open`/`request`);
- вкладки:
  - **Режимы** — опубликованные режимы команды;
  - **О команде** — описание, участники, ссылки;
  - **Участники** — роли и профили;
  - **Новости** — анонсы и обновления (позже);
  - **Статистика** — публичные цифры (позже).

## 9. Модель данных

```text
author_applications
  id, user_id, display_name, about, links_json, planned_content,
  status, reviewed_by, review_note, created_at, reviewed_at

teams
  id, slug, name, description, avatar_url, banner_url, links_json,
  verified, join_mode, status, created_by, created_at, updated_at

team_members
  team_id, user_id, role, sort_order, joined_at
  primary key (team_id, user_id)

team_invites
  id, team_id, code, role, created_by, expires_at, max_uses, used_count

team_join_requests
  id, team_id, user_id, message, status, created_at, reviewed_by, reviewed_at

team_followers
  team_id, user_id, created_at
  primary key (team_id, user_id)

team_news
  id, team_id, author_id, title, body, published_at

modes.team_id
  nullable uuid -> teams
```

`modes.author_id` остаётся для индивидуальных авторов и совместимости. Если у режима есть `team_id`, публичная страница ведёт на команду.

## 11. Основные сценарии

### Стать автором

```text
Аккаунт → Заявка → Модерация → Роль author → Команда
```

### Создать команду

```text
Роль author → Создать команду → Slug → Профиль → Пригласить участников
```

### Опубликовать режим от команды

```text
Команда → Новый режим → Черновик → Релиз → Загрузка файлов → Submit → Approve
```

### Вступить в команду

```text
Публичная страница → Вступить → Заявка → Owner/Admin approve
```

### Пригласить участника

```text
Команда → Участники → Создать инвайт → Ссылка/код → Вступление
```

## 12. Модерация и проверка

- Заявки авторов проверяются вручную на MVP.
- Первый релиз команды проверяется вручную.
- Verified-бейдж выдаётся после проверки команды.
- Жалобы на команду и участников.
- Санкции: предупреждение, скрытие режима, заморозка публикации, блокировка.
- Журнал действий модераторов.

## 13. Безопасность и злоупотребления

- Защита от захвата известных имён.
- Запрет на выдачу себя за другую команду.
- Ограничение количества команд на пользователя.
- Инвайты с ограничением срока и количества использований.
- Нельзя удалить команду с опубликованными режимами без архивации.
- Споры о владении решаются через модерацию.
- Логи входов, приглашений и смены ролей.
- 2FA для owner/admin позже.

## 15. Миграция текущих данных

1. Создать команду `tm` с владельцем `TM`.
2. Привязать `night-demon` и `eclipse` к команде `tm`.
3. Оставить `author`/`authors` в `modes.json` для старых лаунчеров.
4. В новом API использовать `modes.team_id` и `mode_authors`.
5. Старые карточки продолжают показывать автора TM.
